# M6 – Machine paths and GRBL XYZ export

Implemented on 11 October 2026. The generated painting strokes feed a shared XYZ machine program. Simulation and Export both use this program: it includes safe lifts, colour changes, paint reloads at the exact exhaustion point, configurable container procedures, final wash/wipe and parking. Stroke ordering follows the persisted Simulation checkbox; ordering preserves stroke geometry and direction. Optional stroke joining adds short painted bridges, as described below.

## Configure the machine in Workspace

The machine area supplies XY limits and general safe Z. The XYZ settings specify machine Z limits, painting Z range, travel feed, vertical feed and a separate canvas travel Z. Moves whose entire raised XY route stays inside the canvas use canvas travel Z; travel to service zones uses the greatest configured clearance. All positions are absolute millimetres in the same machine coordinate system. Increasing Z raises the brush. Stroke pressure maps linearly from painting maximum Z at pressure 0 to minimum Z at pressure 1.

Double-click a paint container, water zone or wiping area to open its procedure editor. Each physical zone has:

- Clearance Z above the rim and brush holder clearance.
- Service speed in mm/min and repeat count.
- An ordered sequence of X/Y offsets from the zone centre, absolute Z, and dwell seconds after arrival.

The machine travels above the greatest clearance of all containers and the general safe Z. At a service zone, it first positions above the first waypoint, lowers vertically, executes the waypoint sequence and repeats, then raises vertically before leaving. Use waypoints for dipping, lateral shaking, vertical pumping, stirring approximated with polygonal points, or wiping. The separate wiping area runs after washing and before the next paint load. The default water template shakes laterally three times; default loading dips and waits 1.5 seconds. These are editable starting values, not physical calibration. Zones are rectangular movement envelopes; configure them so the validated brush footprint lies within the usable container or wiping area.

The initial wash/wipe can be disabled in Workspace when starting with a prepared brush. Machine paths are calculated when entering Simulation. Changing paint-load capacity or stroke ordering marks the displayed plan out of date. Recalculate machine paths applies the settings without regenerating painting strokes, resets playback and refreshes the load counts and duration. Until recalculation, playback and export are blocked; Export consumes the exact calculated Simulation program and also rejects outdated snapshots when opened directly. Paint-load length counts accumulated painting distance only, excluding raised travel. Procedure settings are saved in project JSON and reusable machine layout profiles, including physical paint slots when palette identities change. Legacy projects without these optional workspace fields receive defaults.

## Optional stroke joining and timing

Simulation offers Connect nearby same-colour strokes and a maximum gap in millimetres. Joining is disabled by default because a painted connector can change a dotted texture. It joins consecutive compatible strokes after ordering, preserving their direction, pressure, feed and phase. Shadow strokes remain separate. The entire conservative brush footprint of each bridge must fit within the source colour region and canvas; masked pixels and other colours block joining. Source colour data is required. Paint capacity still splits a joined path at the exact exhaustion point.

The planner compares complete service-inclusive duration with the unjoined program. If joining introduces extra reloads and makes the program slower, it retains the unjoined program. Simulation reports the accepted joins, added painting distance and saved time, plus separate painting, raised XY travel, vertical motion, loading and washing/wiping durations. Changes require Recalculate machine paths and are shared with Export.

Ordering uses nearest-start selection followed by two bounded passes of directed single-stroke relocation. It accepts only shorter raised travel and does not reverse strokes or cross colour, phase or explicit-operation barriers. This is a heuristic, not a guaranteed global optimum.

## FluidNC motion profile

Workspace and Simulation expose the same saved profile. Copy axes.x/y/z.max_rate_mm_per_min, acceleration_mm_per_sec2 and top-level junction_deviation_mm from the actual FluidNC configuration. UI maximum rates use mm/min (multiply mm/s by 60), accelerations use mm/s², and junction deviation uses mm (FluidNC range 0.01–1). Sample values are disabled by default. Enable Include acceleration and axis limits and recalculate paths to apply. Profile changes invalidate the Simulation/Export snapshot, like other machine settings. Profiles persist in project JSON and reusable Workspace profiles. Start speed is calculated from the velocity plan instead of being a separate user parameter; the beginning, end, reversals and G4 dwell force a stop, while compatible collinear segments can continue.

G-code uses the existing G21/G90/G94/G1/G4 dialect accepted by FluidNC and GRBL. Export documents the assumed motion configuration in comments but does not write controller settings, pins, homing, steps/mm or firmware YAML. Calibrate these on the controller. Junction deviation limits speed; the planner does not change the painted geometry. Joining comparisons include the selected acceleration model for both candidate and baseline.

## Rough paint consumption

Simulation displays per-colour cards and a total beneath the timeline. Painting distance comes from the applied machine timeline, including accepted joining bridges and overlapping strokes. Raised travel and service movement do not add painting distance. Cards also report logical load counts; repeated procedure waypoints and dwell do not inflate them.

Estimated ml = painted metres × ml per metre + colour cleaning cycles × waste per cleaning. A complete wash/wipe sequence counts once; the initial wash of an empty brush adds no colour waste. The illustrative starting coefficients (0.5 ml/m and 0.05 ml per cleaning) are labelled as uncalibrated and do not claim measured material properties. Users can edit empirical coefficients for their brush, paint mixture, pressure and surface in Calibrate paint consumption, then recalculate in the preview header. Calibration persists with the Workspace machine profile. Invalid paths show consumption unavailable. This is an approximate material allowance, not a wet-paint fluid simulation; it does not calculate unique covered area or container dead volume.

## Validation and routes

The planner checks finite values, pressure, positive feeds/capacity, canvas stroke bounds, XYZ machine limits, service waypoint footprint with half-brush clearance, missing paint cups and workspace geometry. Raised travel uses a visibility graph around rectangular forbidden zones, expanded by half the brush width. If no route exists, or a painting/service path hits a forbidden zone, playback and export are blocked. The brush width is used as a conservative rectangular footprint; a larger holder requires correspondingly larger keep-out zones and clearance heights. A Z origin and actual container heights must be calibrated on the target machine.

## Export

Export displays the XY paths, validation errors, painting statistics and a text preview. Both native save dialogs and browser downloads produce a complete .gcode file. Dry run is selected initially; it follows the same XY route at clearance Z, suppressing immersion, painting depth and dwell.

The GRBL program uses G21, G90, G94, controlled G1 XYZ moves, G4 P dwell in seconds, and initial/final raised Z. The starting XY position is the configured parking point. The machine must already be homed and parked with the same coordinate origin; the export does not issue homing commands or reset offsets. Time estimates include XYZ motion and dwell, excluding initial lifting from an unknown real Z. The optional FluidNC motion profile adds directional XYZ speed/acceleration limits, triangular or trapezoidal velocity, braking, and junction-deviation corner slowdown with forward/backward lookahead. Playback position and paint consumption follow the velocity profile; exported G1 feeds are capped by axis component limits. This is a Cartesian estimate with whole-program lookahead, not a firmware emulator: finite planner buffering, step quantisation, streaming starvation and non-Cartesian kinematics can change actual time. No device streaming, servo postprocessor or real-machine verification is included.

The original M0 toGrbl function remains available for its standalone prototype. Application export uses machineProgramToGrbl and the full service program.

## Verification

Machine planning tests replay the exported commands independently and compare position, movement count and elapsed time with Simulation. Further tests cover exact stroke resumption, vertical container entry, repeat/wash/wipe order, raised travel, detours, unreachable routes, invalid XYZ data, dry run, and persistence through projects and layout profiles. UI tests cover saving, blocked/stale plans and editing service points.

Simulation supports 50–400% zoom with the wheel, a slider or buttons, drag panning, and Fit to view. Display zoom does not change the painting raster resolution or generated machine paths. Recalculating paths preserves the viewport.

## Calculation progress

Stroke generation, wet-paint preview rendering and machine path calculation run in disposable Web Workers. Each job publishes its current stage to an accessible animated progress bar; the bar is indeterminate because the synchronous algorithms do not report a measured completion fraction. Reduced-motion preferences disable its animation. Repeated generation/recalculation is disabled while busy, navigation aborts the current job, and late results cannot replace the active project. Errors clear the busy state and allow retry. During path recalculation the previous statistics remain visible; playback and export wait for a successful current calculation.
